# DotaPulse — архитектура продукта

## Цель
Адаптивный веб-сервис для игроков Dota 2. Продукт превращает публичные игровые данные в понятные гипотезы для улучшения игры. Первый релиз бесплатный и собирает обратную связь.

## Принципы
- Не запрашивать пароль Steam и не хранить Steam-токены.
- Использовать публичные данные OpenDota и соблюдать их лимиты/условия.
- Отделять измеренные факты от гипотез тренера.
- Не выдавать KDA или винрейт за полную оценку качества игрока.
- Не публиковать персональные профили без действия пользователя.
- Не обещать гарантированный рост MMR.

## Слои системы

### 1. Frontend (сейчас: `dotapulse/index.html`)
- Mobile-first адаптивный интерфейс.
- Ввод Account ID.
- Профиль, последние матчи, KDA, винрейт, герои.
- Объяснимые рекомендации MVP.
- В следующем релизе: история сессий, сравнение периодов, onboarding, доступность и локализация.

### 2. API / Backend (следующий этап)
Рекомендуемый стек: Python 3.12 + FastAPI.
- `GET /api/v1/players/{account_id}/overview`
- `GET /api/v1/players/{account_id}/matches?limit=50`
- `GET /api/v1/players/{account_id}/hero-insights`
- `POST /api/v1/coach/review`
- `GET /api/v1/players/{account_id}/progress?from=&to=`

Backend должен валидировать Account ID, кешировать ответы OpenDota, ограничивать частоту запросов и нормализовать схему данных. Ключи внешних AI-провайдеров никогда не помещать во frontend.

### 3. Data provider
OpenDota API:
- Player profile
- Recent matches
- Player heroes
- Match details (по необходимости)
Сохранять источник и время получения данных. Учитывать пропуски и непубличные данные.

### 4. Analytics engine
Сначала детерминированные, тестируемые правила:
- агрегаты по матчам и ролям (только если роль доступна);
- динамика по скользящим окнам;
- hero pool при минимальном числе матчей;
- сравнение личных периодов;
- предупреждение о малой выборке.
Каждая рекомендация содержит: наблюдение, возможную интерпретацию, что проверить в реплее, уверенность/ограничения.

### 5. AI coach
AI не должен придумывать игровые события. В модель передаётся компактный JSON с проверенными агрегатами и фактами матча. Ответ возвращается по строгой схеме:
- summary
- strengths[]
- improvement_areas[]
- evidence[]
- next_session_plan[]
- uncertainty_notes[]
Проверять выводы пост-обработкой; явно помечать предположения. Не отправлять Steam credentials или лишние идентификаторы.

### 6. Persistence
Для MVP без аккаунтов можно хранить историю только в браузере (с явным уведомлением).
Для публичного запуска: PostgreSQL для пользователей, агрегатов и истории; Redis для кеша и rate-limit. Собирать минимум данных, предусмотреть удаление аккаунта и выгрузку данных.

### 7. Hosting / delivery
- Frontend: GitHub Pages или Cloudflare Pages.
- Backend: Render / Fly.io / Railway или VPS после выбора региона и проверки условий.
- CI: GitHub Actions (lint, unit tests, deploy).
- Secrets: только в secrets-хранилище платформы.

## Схема потока
1. Пользователь вводит Account ID.
2. Frontend обращается к backend.
3. Backend проверяет формат и кеш.
4. При необходимости получает данные OpenDota.
5. Analytics engine рассчитывает метрики и evidence.
6. AI coach формирует объяснение на основе evidence.
7. Frontend показывает выводы, ограничения и план следующей тренировки.

## Этапы разработки
- MVP 0.2: профиль, последние матчи, корректный подсчёт побед, герои, базовые объяснимые рекомендации.
- 0.3: backend proxy, кеш, история периодов, unit tests.
- 0.4: разбор конкретных матчей и реплеев, role-aware метрики.
- 0.5: AI coach с JSON schema и защитой от выдуманных фактов.
- Beta: тестирование с 10–20 игроками, метрики активации и возврата.
- Monetization: только после подтверждения регулярной ценности продукта.

## Критерии качества
- Победа вычисляется по player_slot и radiant_win; неизвестный результат не считается поражением.
- При пустых/частичных данных UI не падает.
- Для hero insights показывается размер выборки.
- Каждая рекомендация ссылается на конкретную метрику/матчи.
- Ошибки API и rate limit показываются понятным сообщением.
- Проверить на мобильных экранах и актуальных браузерах.

## Текущие ограничения MVP
Это клиентский прототип без backend и настоящей LLM. Он использует OpenDota напрямую из браузера. Правила тренера являются эвристиками и не доказывают причин проигрыша. Для публичной эксплуатации нужен backend proxy, кеширование, мониторинг и тесты.
